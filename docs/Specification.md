# Tau 2.0 Specification

Tau 2.0 is an innovative language model framework designed to work within the Hugging Face ecosystem. Instead of using low-dimensional, tokenized inputs from methods like Byte-Pair Encoding, Tau is trained directly on high-dimensional embedding data generated by Sentence Transformers. Its unique pipeline processes embeddings as the input action space and outputs a PCA-optimized 3D embedding that represents a word. A fast retrieval layer that uses ANN/HNSW algorithms matches this output to a corresponding vocabulary word or phrase.

## Project Overview

Tau 2.0 leverages a PPO+DQN architecture tailored for high-dimensional embeddings. The primary stages in the pipeline are:

- **Input Generation:** Chunks of text are transformed into high-dimensional embeddings using Sentence Transformers.
- **Model Processing:** A PPO-trained DQN ingests these embeddings and outputs a compressed 3-dimensional representation via PCA.
- **Retrieval:** The 3D output is matched against a pre-computed vocabulary index using Approximate Nearest Neighbor (ANN) or HNSW search, retrieving the best-matching word or phrase.

This design enables Tau to bypass traditional tokenization and work directly with rich semantic embeddings.

---

## Design Goals

- **Modularity:** Separation of model, training, data handling, and retrieval components.
- **HF Ecosystem Integration:** Adherence to naming conventions and API design similar to Hugging Face’s libraries (e.g., transformers).
- **Configurability:** Global configuration utilities and dedicated hyperparameters files for consistent training across models.
- **Efficiency:** ONNX export functionality for optimized inference alongside robust ANN/HNSW retrieval.
- **Modern Packaging:** Use of the `uv` package manager and `pyproject.toml` for dependency management and packaging.

---

## Architecture Overview

1. **Input Embedding Processing:**
   - Uses Sentence Transformers to generate high-dimensional embeddings from text.
2. **PPO+DQN Model:**
   - The model (in `modeling_ppo_dqn.py`) processes embeddings using a mix of PPO training techniques and DQN architectures, yielding a PCA-optimized 3D vector.
3. **Retrieval Module:**
   - ANN/HNSW algorithms in the `retrieval/` module convert the numeric 3D output to human-readable text by matching against a vocabulary index.
4. **ONNX Export:**
   - Models can be exported to ONNX format for portability and performance optimization.

## Configuration & Hyperparameters

- **`configuration_tau.py`:**  
  Loads and manages configuration parameters for model architectures and training settings.

- **`configs/tau_hyperparameters.yaml`:**  
  Contains a centralized collection of hyperparameters (learning rates, layer dimensions, dropout rates, etc.) that are applied across all models.

- **`configs/tau_ppo_dqn_config.yaml`:**  
  Includes overall training configuration such as file paths, runtime parameters, and specific training strategies.

---

## Package Manager & Build Tools

- **uv Package Manager:**  
  We are using the UV package manager for dependency management, which modernizes our workflow compared to traditional requirements files.

- **`pyproject.toml`:**  
  This file is our single source of truth for build configuration, dependencies, and package metadata. It replaces the need for a `setup.py` and `requirements.txt`.

---

## Integration & Export

- **ONNX Export Support:**  
  The `export_onnx.py` module contains utilities that allow model export to the standardized ONNX format, ensuring model portability and optimized inference across platforms.

- **Retrieval Algorithms:**  
  The `retrieval` module implements ANN/HNSW techniques (in `ann_matcher.py`) to match the model's low-dimensional output with a vocabulary index (`vocab_index.py`), converting numeric representations back into human-readable text.

---

## Testing & CI/CD

- **Unit Testing:**  
  Comprehensive tests are provided under the `tests/` directory to ensure each module works correctly (configuration loading, model training, dataset processing, and retrieval operations).

- **CI/CD:**  
  GitHub workflows under `.github/workflows/` run automated tests, build documentation, and manage package publishing to PyPI.
